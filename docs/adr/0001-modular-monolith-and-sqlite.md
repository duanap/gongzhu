# 采用模块化单体和 SQLite 作为管理数据基础

本项目继续以单进程模块化单体承载 HTTP、WebSocket 和牌局规则，实时房间仍保存在进程内存中；玩家、牌局、管理员会话、幂等结果和审计条目统一持久化到 SQLite。该选择符合当前单实例 PM2 部署和较小数据规模，避免过早引入独立服务与网络一致性成本，同时通过应用层接口、版本化 `/api/admin/v1` 和安全投影保留以后迁移到外部数据库或独立后台服务的边界。

## Consequences

- 生产运行时要求 Node.js 22.13 或更高版本，并保持 PM2 `instances: 1`、`exec_mode: 'fork'`。
- 旧 `data/users.json` 会在空数据库首次启动时自动导入；显式设置 `DATA_BACKEND=json` 可临时回退，但管理 API 在 JSON 后端下不可用。
- SQLite 文件和 WAL 文件必须作为运行数据持久化、备份，不能随发布包覆盖。
- 若以后需要多实例或跨进程实时房间管理，必须先把实时房间状态迁移到共享存储或有明确所有权的房间服务。

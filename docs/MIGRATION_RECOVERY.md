# 客户端迁移补救执行约束

## 当前恢复基线

- GitHub `main` 根提交：`0d0cb6ec6ff91f8166f315355476f9170891266f`。
- 根路径 `/` 继续指向旧版稳定客户端。
- `/vue/` 仅用于迁移验收，不允许直接替换 `/`。
- 当前 Vue WIP 已完整包含在恢复基线中，不再通过继续堆叠组件和全局 CSS 的方式修补。

## 当前阶段目标

1. 先把旧版功能、位置、布局、时序和设置行为记录为等价性契约。
2. 在修改旧版或 Vue 表现之前建立浏览器流程和视觉回归保护。
3. 在测试保护下模块化旧版，再决定是否重新启动 Vue 迁移。

## 架构结论

保留 `/` 旧版、以 `/vue/` 灰度运行新客户端的双入口架构是合理的；服务端继续作为唯一牌局状态源、两个客户端共用同一 WebSocket 协议，也适合渐进迁移。当前问题不在 Vue 本身，而在迁移过程中把“组件重写、布局重做、交互改版”同时进行了，导致组件数量增加却失去旧版行为契约。

补救时不需要推倒 Vue，也不能继续按页面观感补洞。后续采用以下边界：

1. 旧版只做阻塞验收的缺陷修复，不再扩展新玩法。
2. Vue 先以本矩阵和截图基线恢复行为等价，不把视觉改版混入迁移提交。
3. WebSocket 消息转换集中在客户端适配层，组件只消费稳定的视图状态；禁止组件各自解释服务端阶段和玩家索引。
4. 按“房间、传牌、出牌与收墩、结算、设置与工具”纵向切片验收，每个切片同时覆盖流程、布局和时序后才算迁移完成。
5. 根路径切换必须以等价矩阵全部清零、双真机人工验收和可一键回滚为前提。

## 明确不做

- 不切换生产根路径。
- 不在本阶段重做牌桌布局或视觉风格。
- 不同时修改服务端规则与客户端迁移架构。
- 不使用竖屏窗口中的 CSS 旋转截图冒充真实横屏截图。

## 横屏验收模式

### 物理横屏

物理横屏是正式验收基线。浏览器窗口、页面 viewport、模拟 screen、方向媒体查询和截图文件必须同时为横屏。游戏根节点不得存在 90 度旋转。

截图前必须验证：

- `outerWidth > outerHeight`
- `innerWidth > innerHeight`
- `screen.width > screen.height`
- `matchMedia('(orientation: landscape)').matches === true`
- `screen.orientation.type` 以 `landscape-` 开头
- 游戏根节点计算旋转角度接近 0 度
- PNG 宽度大于高度

任一条件失败时不得生成或比较验收基线。

### CSS 强制横屏降级

CSS 强制横屏只用于无法锁定设备方向时的兼容验证。它使用竖屏 viewport 和 `force-landscape` 旋转页面，必须使用独立测试名称和独立截图目录，不能用于批准物理横屏。

## 变更门槛

每一项客户端迁移变更必须：

1. 指向等价矩阵中的具体条目。
2. 先有失败的窄范围测试或明确的人工复现步骤。
3. 不改变旧版入口及未涉及功能。
4. 通过服务端测试、双入口 smoke 和相关浏览器检查。

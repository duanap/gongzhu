## 物理横屏证据规则

物理横屏截图必须同时带有 `.orientation.json` 证据。浏览器窗口、viewport、screen、方向媒体查询、方向 API、根节点旋转角度或截图尺寸任一不合格，测试立即失败，并且不得写入验收截图。

## 人工真机门槛

正式切换前至少使用一台 Android Chrome 和一台 iPhone Safari 物理旋转到横屏，截取包含设备屏幕或浏览器边界的证据。真机证据不能被桌面窗口缩放或 CSS 强制旋转截图替代。

## 剩余项处理顺序

1. 本地证据维护：代码变更后持续回归已清零的 ROOM-04、EVENT-02/04/05/06、PANEL-01、DATA-01，不得用独立新版截图替代旧版/Vue 几何对照。
2. 公网账号验证：DATA-02、DATA-03 使用真实 QQ 测试账号和公网数据验证，只归档脱敏结果，不记录 Cookie、token 或密钥。
3. 双真机验收：Android Chrome 与 iPhone Safari 分别验证系统横屏、全屏、实际听感、动画流畅度和断网重连，并保存设备边界清晰可见的录像或截图。
4. 生产门槛：2026-08-09 已完成 `c1daa56` 灰度部署，本机 smoke 7/7，公网健康、WebSocket 和新版资源可用；但 EdgeOne 缓存覆盖导致公网完整 smoke 为 5/7，且连续 smoke、断网重连和回滚演练尚未完成。在这些项目全部通过前，保持 `/` 为旧版、`/vue/` 为灰度入口。

## 几何对照例外

桌面与 `844×390` 横屏现已直接采集旧版/Vue 的中心圆、四座头像、记分牌和手牌几何并比较。以下差异来自后续明确产品要求，不视为遗漏迁移：Vue 对手牌背最多显示 4 张；左右家牌堆横排在记分牌下；对家牌堆横排在头像左侧；桌面本家头像向左移到下家手牌下方。测试仍会约束这些例外的锚点，避免继续漂移。

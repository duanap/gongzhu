# 红心大战 Hearts Online

## 发布与部署

当前发布策略保持双入口：`/` 是旧版稳定客户端，`/vue/` 是 Vue 灰度入口。部署代码不得顺带把根路径切到 Vue。

正式更新使用“已提交的 Git 快照 + 带 SHA-256 的部署包 + 自动部署脚本”，不要直接在生产目录执行 `git pull`，也不要把整个开发工作区覆盖到服务器。标准流程是：

1. 在明确的发布分支完成提交、推送和 PR，确认提交哈希。
2. 运行 `npm test`、`npm run check:css`、`npm run build:client` 和本地 `npm run check:vue-cutover`。
3. 从该提交生成部署包，排除 `.env`、根目录 `data/`、`uploads/`、`node_modules/`、测试截图和本地分析产物。
4. 将部署包和匹配的部署脚本上传到 `/www/wwwroot/duanap/artifacts/hearts/`。
5. 在服务器校验 SHA-256 后运行脚本。脚本在临时目录安装、测试、构建，保留生产运行数据，备份旧版本，失败时自动回滚。
6. 检查 PM2、本机健康接口、公网双入口、缓存头和 WebSocket。

服务器执行形式：

```bash
cd "/www/wwwroot/duanap/artifacts/hearts"
DEPLOY_ARCHIVE="hearts-by-duanap-1.4.22-20260802-c1daa56-deploy.tar.gz"
DEPLOY_SCRIPT="deploy-hearts-1.4.22-20260802-c1daa56.sh"
chmod 750 "$DEPLOY_SCRIPT"
sha256sum "$DEPLOY_ARCHIVE" "$DEPLOY_SCRIPT"
bash "./$DEPLOY_SCRIPT"
```

以上文件名是最近一次已验证发布物的示例；后续发布必须同时替换包名和脚本名，不能混用不同提交的文件。

该发布物已于 2026-08-09 部署到生产灰度环境：`/` 继续提供旧版，`/vue/` 提供 Vue。PM2、本机 7/7 smoke、公网健康检查、WebSocket 和新版资源访问均正常；公网完整 smoke 目前为 5/7，剩余问题是 EdgeOne 将入口和 `/sw.js` 的缓存头覆盖为 `max-age=0`。详细证据与后续处理见部署手册。

性能和稳定性验收建议：

- 桌面和手机各完整打一局，观察动画是否掉帧、卡住或遮挡。

- Vue 版核心牌局流程已覆盖服务端主要消息：创建/加入、开始、AI 补位、离开、解散、传牌、出牌、甩牌、互动、AI 接管、下一局和再来一局。

- 版本号只在 `package.json` 中维护；旧版、Vue、健康检查均从该值生成显示版本，更新记录统一维护在 `release-info.json`。
- 上线测试前建议清理浏览器本地缓存，避免旧 `roomId` 或 `reconnectToken` 让 Vue 首屏显示残留房间状态。

双真机步骤见 [Android / iPhone 真机横屏验收清单](docs/DEVICE_ACCEPTANCE.md)，当前切换判断见 [Vue 迁移发布评估](docs/RELEASE_READINESS.md)。

## 玩法说明

1. 第一个玩家点击“创建房间”。
2. 系统生成 4 位数字房间号。
3. 把房间号发给其他玩家。
4. 其他玩家输入房间号并点击“加入房间”。
5. 满 4 人会自动开始。
6. 人数不足时，房主可以点击“AI补位开始”。

## 房间超时配置

默认配置：

```txt
所有真人玩家离线 5 分钟后自动解散
房间 60 分钟无活动后自动解散
```

可以通过环境变量修改，单位是毫秒。

例如：

```bash
ROOM_EMPTY_TTL_MS=600000 ROOM_IDLE_TTL_MS=7200000 npm start
```

含义：

```txt
所有真人玩家离线 10 分钟后解散
房间 2 小时无活动后解散
```

Windows CMD 示例：

```bat
set ROOM_EMPTY_TTL_MS=600000
set ROOM_IDLE_TTL_MS=7200000
npm start
```

PM2 示例：

```bash
ROOM_EMPTY_TTL_MS=600000 ROOM_IDLE_TTL_MS=7200000 pm2 start server.js --name hearts
```

## 宝塔生产环境

生产拓扑固定为 EdgeOne → 宝塔 Nginx → `127.0.0.1:3000` → PM2 `hearts`。服务器必须使用 Node.js 22.13 或更高版本，并保持 PM2 `instances: 1`、`exec_mode: fork`；房间与实时牌局在单个 Node.js 进程内存中，不能使用 cluster。

宝塔站点反向代理模板位于 `deploy/nginx-location.conf`，完整安装、更新、备份、回滚和 EdgeOne 缓存规则见 [EdgeOne + 宝塔生产部署手册](deploy/EDGEONE.md)。该手册优先于 README 中的历史命令。

## 常见问题

### 页面能打开，但创建房间失败

大概率是 WebSocket 没有代理成功。检查 Nginx 是否包含：

```nginx
proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
```

并确认这些配置位于 `/ws` 的 location 中。可直接使用 `deploy/nginx-location.conf`。

### 域名访问 502

检查 Node 服务是否运行：

```bash
pm2 list
ss -tunlp | grep 3000
pm2 logs hearts
```

### 房间突然消失

可能是触发了自动解散规则：

- 所有真人玩家都离线超过默认 5 分钟；
- 房间超过默认 60 分钟没有操作。

需要延长时间时，调整 `ROOM_EMPTY_TTL_MS` 和 `ROOM_IDLE_TTL_MS`。

## 互动配音文件建议

后续要给【互动】里的文案加配音时，建议把音频统一打包成一个 zip 发过来，目录结构如下：

```text
public/audio/interactions/
├── good_job.mp3
├── hurry_up.mp3
├── little_flying_stick.mp3
├── stop_him.mp3
├── shoot_moon.mp3
├── who_understands.mp3
├── check_cards.mp3
├── cards_ok.mp3
├── xiaobiesan.mp3
├── xiaoerke.mp3
├── polish_shoes.mp3
├── flower.mp3
├── tomato.mp3
├── applause.mp3
└── like.mp3
```

推荐使用 `mp3`，单个文件尽量控制在 `200KB` 内，时长 `0.5-2 秒`，避免影响 PWA 首次加载。
